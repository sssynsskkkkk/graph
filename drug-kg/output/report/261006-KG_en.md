## 1. How the Web Page Content Was Collected

### 1.1 Target selection and URL resolution
- Drugs.com has no ranking page (the home page only shows an alphabetical list of ~100 popular drugs), so we used **the drugs among the ClinCalc DrugStats top 50 by prescription volume that have a Drugs.com page** (`drugs/top50.yaml`).
- Each generic name is converted to a slug and `https://www.drugs.com/<slug>.html` is tried first; on failure, candidate slugs are tried in order. The mapping is saved to `data/drug_urls.json` and reused.
- Four drugs needed a non-default slug: Dextroamphetamine+Amphetamine → `adderall`, Fluticasone → `flonase`, Acetaminophen+Hydrocodone → `hydrocodone-acetaminophen`, Ergocalciferol → `mtm/ergocalciferol` (resolved via an alternative slug after four 404s).

### 1.2 Access blocking and countermeasures (Akamai Bot Manager)
- `robots.txt` blocks AI crawlers (ClaudeBot, GPTBot, etc.) entirely and disallows only a few paths for general user agents, such as `/api/`, `/search.php`, and `/drug-interactions-all/`. Drug detail pages are allowed.
- A plain `curl` request returned 403 (Access Denied). The following combination returned 200:
  1. A header set identical to Chrome's (User-Agent, Accept, Accept-Language, Sec-Fetch-*, sec-ch-ua, etc.)
  2. A `requests.Session` that first opens the home page to obtain cookies (`bm_s`, `bm_so`, `ddc-detect-cookie`) before requesting drug pages
  3. A random delay of 6–10 seconds between requests
- Intermittent 403s still occurred (**33** in total), so we added a recovery routine: on 403/429, wait 45 s × attempt number → discard the session (cookies) and warm up a new one → retry up to 4 times → if still failing, fall back to an Internet Archive (Wayback) snapshot (not used in this run).
- Downloaded HTML is cached in `data/raw_html/`, so re-runs do not touch the network. Collection took about 39 minutes including 403 back-off waits (50 pages, measured from logs).

### 1.3 Page parsing (`drugkg/parse.py`)
Two kinds of information are extracted from each page.

**(a) Structured metadata** (rule-based, no LLM, high precision)
- `h1` title; `p.drug-subtitle`: generic name and pronunciation, brand names (with discontinued status), dosage forms and strengths, drug class (link)
- JSON-LD (`MedicalWebPage`): description, last-modified date, reviewer. `FAQPage`: list of Q&As
- Info box: availability (Rx/OTC), CSA controlled-substance schedule, FDA approval year
- "Related/similar drugs" carousel: 10 related drugs

**(b) Section text**: for each `h2` inside `<main>`, the sibling elements up to the next `h2` are flattened. `p` becomes a paragraph, `ul/ol` items become "- item", `h3` becomes a "Subheading:" line, `dl` becomes "term: definition", tables become "cell | cell", and `details` becomes summary + body. Ads, the interaction-checker box, and carousels (`ddc-box`, `ddc-mgb`, `ddc-carousel`, `noprint`, etc.) are skipped. Non-content sections such as "More about", "References", "Related drugs", and "Popular FAQ" are excluded.

### 1.4 Chunking (`drugkg/chunk.py`)
- Paragraphs are grouped per section into chunks of **at most 1,100 characters**; trailing chunks shorter than 150 characters are merged into the previous chunk. Long paragraphs are split at sentence boundaries.
- Each chunk carries a `chunk_id` (slug#section#index), the drug name, the section heading, and the source URL, which are propagated to the final triples as provenance.
- Result: 834 chunks, 570,620 characters in total. Chunks per section: dosage 132, side-effects 112, before-taking 85, warnings 77, interactions 72, uses 59, directions 52, overdose 48, missed-dose 46, what-to-avoid 46, other 105.

### 1.5 Data usage note
Drugs.com content is copyrighted, so its use is limited to non-commercial coursework. Every triple keeps the source URL and section/chunk id so its origin can be traced.

## 2. Current KG Construction Procedure

```
raw HTML ─parse─▶ metadata + section text ─chunk─▶ 834 chunks
                        │                              │
                        │                     ① Extract (OIE, few-shot)  → 11,140 open triplets
                        │                     ② Define (relation definitions)
                        │                     ③ Canonicalize (top-5 definition-embedding retrieval + LLM multiple choice; enrich schema on failure)
                        ▼                              ▼
              969 structured triples          10,411 canonicalized triples (schema 40 → 193)
                        └──────────────┬───────────────┘
           ④ Consolidate (merge enriched relations) ⑤ Post-process (aliases, types, dedup) ⑥ Export
```

### 2.1 Runtime environment
- Qwen3-4B-Instruct-2507 is served with vLLM 0.31 as an OpenAI-compatible API (`localhost:8000/v1`). Because the GPU (RTX 3090 Ti, 24 GB) is shared with other jobs, we used the 4B model instead of 7B (50% of GPU memory).
- Relation definitions are embedded with bge-base-en-v1.5 (CPU). All LLM calls are cached in `output/cache/llm/`, so re-runs and resumption cost nothing. Up to 16 concurrent requests are batched by vLLM.

### 2.2 ① Extract: Open Information Extraction
- We use the paper's OIE template, but add context to every chunk: "this text comes from the {section} of the Drugs.com page for **{drug}**, and 'this medicine'/'it' refers to {drug}". This resolves pronouns to the drug entity.
- Five drug-domain few-shot examples (uses / warnings / side effects / interactions / dosage) are provided. To prevent schema explosion with a small model, we added the instruction "relation names should be generic, reusable 2–4 word phrases; put specifics (dose, population, condition) in the object". Before this instruction the first drug produced 12 enriched relations; after it, 5.
- The output is a JSON list; on parse failure we fall back to the bracket-matching parser used in the paper's code. Result: extraction succeeded for all 834 chunks, producing 11,140 open triplets with 1,409 distinct raw relations (top: has side effect 1,788, interacts with 756, has administration instruction 716, has warning 664, treats 373).

### 2.3 ② Define: Schema Definition
- Given a chunk, its triples, and the list of relations, the LLM writes a one-line general definition per relation that makes the subject/object direction explicit (paper template + 3 domain few-shot examples).
- Example: `has withdrawal symptom: When the subject drug is stopped abruptly, the patient may experience the symptom specified by the object entity.`
- These definitions are the retrieval keys for the next step, so canonicalization is based on the relation's **meaning**, not its **name**.

### 2.4 ③ Canonicalize: seed-schema alignment + self-canonicalization (hybrid)
- Seed schema of 40 relations (`schemas/drug_seed_schema.csv`): treats, has side effect, has serious side effect, interacts with, contraindicated in, use with caution in, has recommended dose, has dosage form, belongs to drug class, has mechanism of action, has boxed warning, has administration/missed dose/overdose/storage instruction, etc. Each relation also defines subject/object types (e.g., Drug→Condition).
- Procedure: (1) if the relation name already exists in the schema, keep it (direct). (2) Otherwise retrieve the top-5 schema candidates by definition embedding and ask the LLM with the paper's verification prompt, "which of A–E can replace it / F. None of the above" (mapped). (3) If the answer is None, first compare against relations newly added in the same batch (mapped_new), then add the relation to the schema with its definition and LLM-assigned types (enriched).
- Results (11,140 triplets): direct 6,928 (62.2%), mapped 4,022 (36.1%), mapped_new 35, auto 2, **enriched 153 (1.4%)**. In hybrid mode no triple is discarded.
- Schema size over time: 40 → 45 (1 drug) → 135 (26 drugs) → 193 (50 drugs). Growth slowed as more drugs were processed; 61 of the 153 enriched relations are used 5 or more times.

### 2.5 ④ Consolidate and filtering
- After extraction, for enriched relations whose definition similarity to another relation (enriched or seed) is ≥ 0.80, the LLM is asked yes/no "do these two relations mean the same thing?" and merges are applied. The 4B model said yes only to obvious synonyms (`is used to treat` → `treats`), so there were 0 automatic merges; one manual merge, `has instruction` → `has administration instruction`, was added in `config.yaml`.
- Enriched relations used only once are dropped from the final KG (193 → 147 relations).

### 2.6 Structured triples (969)
Parsed metadata is added as high-precision triples: has generic name, has brand name (204), belongs to drug class (110), has dosage form (224), has strength (234), similar to (496, from the related-drugs carousel), has availability, fda approval year, has controlled substance schedule.

### 2.7 ⑤ Post-processing and ⑥ Export
- Drug aliases (title, "this medicine", slug, parenthesized abbreviations such as HCTZ) are merged into the drug node; entity strings are normalized (articles, quotes, and punctuation removed; lowercase key); entity types are decided by voting over the relations' domain/range types (Drug takes priority); duplicate (subject, relation, object) triples are merged while keeping counts, source drugs, and chunk provenance.
- Outputs: `triples.jsonl/csv`, `entities.csv`, `schema.csv`, `neo4j/` (nodes/relationships CSV + Cypher), `kg.ttl` (RDF), `kg.graphml`, `stats.json`.

### 2.8 Differences from the EDC paper
| Aspect | Paper | This implementation |
|---|---|---|
| Input unit | Single sentence | Section-based chunk (~1,100 chars) + drug name/section context |
| LLM | GPT-3.5/4, Mistral-7B | Qwen3-4B-Instruct (local) |
| Embedder | e5-mistral-7b-instruct | bge-base-en-v1.5 |
| Schema | Target alignment or self-canonicalization | Hybrid: 40 domain seed relations + enrichment, with relation types (domain/range) |
| Canonicalization parallelism | Sequential | Batched verification; only new relations checked sequentially for duplicates |
| Additional steps | – | Consolidate (merge enriched relations), structured metadata triples, provenance, multi-format export |
| Refinement (EDC+R) | Schema retriever + entity hints | Implemented (`--iterations 1`), not used in the default run due to cost |

### 3.2 Connectivity (usefulness as a KG)
- 1,074 object entities are shared by 2 or more drugs, and 103 by 10 or more. Most shared: allergic reaction (47 drugs), nausea (43), headache (39), vomiting (36), dizziness (36), diarrhea (32). This enables cross-drug queries such as "drugs with the same side effect" or "drugs contraindicated in a given condition".
- 100 direct edges among the 50 drugs: similar to 50, interacts with 34 (e.g., Adderall→Tramadol, Apixaban→Clopidogrel/Ibuprofen/Warfarin), increases level of 6, used in combination with 4, should be avoided with 3.
- Groups sharing a drug class: SSRIs (Escitalopram, Fluoxetine, Sertraline), statins (Atorvastatin, Rosuvastatin, Simvastatin), PPIs (Omeprazole, Pantoprazole), etc., enabling 2-hop queries.
- 661 triples were extracted 2 or more times from different chunks; repeated extraction can serve as a confidence signal (`count` field).

### 3.3 Quality observations (sample review)
Good examples:
- `Bupropion — has maximum dose → 450 mg/day in up to 4 divided doses`
- `Metformin — contraindicated in → severe kidney disease`, `Metformin — requires monitoring of → estimated glomerular filtration rate`
- `Simvastatin — increases level of → HDL cholesterol`, `Apixaban — interacts with → Warfarin`
- `Sertraline — has onset of effect → up to 12 weeks`

Problem types and (estimated) frequency:
1. **Wrong relation choice**: `Pantoprazole — has warning → blood in urine` (should be serious side effect), `Metformin — lowers level of → acne`, `Bupropion — treats → weight gain`. These arise when the 4B verifier picks the most similar candidate, and they are the most common quality issue.
2. **Wrong subject**: 13 triples (0.1%) whose subject is not a drug, e.g., `regular ovulation — has mechanism of action → reduced androgen levels`.
3. **Sentence-like objects**: about 1,600 Instruction/Warning objects are close to sentences, such as "take only once daily with evening meal", which limits their reuse as nodes. The information is preserved but is less useful for graph queries.
4. **Uninformative shared nodes**: boilerplate such as `report side effects to FDA at 1-800-FDA-1088` (47 drugs), `call Poison Help line` (39), and `seek emergency medical attention` (39) become hub nodes. They can be cleaned with a removal list (`postprocess.drop_relations` or an entity filter).
5. **Entity variants**: form/brand variants such as `Adderall`/`Adderall XR`, `Albuterol Inhalation`/`albuterol`, and `Furoscix ReadyFlow` remain separate nodes. Some objects also contain relation words (`treats ADHD`).
6. **Quality of enriched relations**: top enriched relations such as `has maximum dose` (72), `has inactive ingredient` (61), `has withdrawal symptom` (47), `has disposal instruction` (21), and `not used to treat` (29) are useful relations missing from the seed schema, while others such as `has product variation`, `has side effect variation`, and `should not be taken` are vague. Reviewing the top enriched relations as candidates for the seed schema is the most effective step for the next iteration.

### 3.4 Limitations and improvement plan
- **Model size**: canonicalization verification and OIE quality depend heavily on the model. When the GPU is free, re-running with Qwen2.5-7B-Instruct or larger via `--stage extract --force` is recommended (the prompt cache is separated per model).
- **No quantitative evaluation yet**: only sample review has been done so far. Before the presentation we propose manually scoring a stratified sample of 100–200 triples per relation group to report precision (the provenance in `triples.jsonl` allows checking against the source text).
- **Entity normalization**: merging brand/form variants, removing boilerplate nodes, and summarizing Instruction objects into short canonical forms are needed.
- **Type-constraint validation**: automatically flagging triples whose entity types violate the relation's domain/range (e.g., treats → SideEffect) can filter wrongly chosen relations.
- **Coverage expansion**: adding `sfx` (detailed side effects) and `dosage` (dosage guide) to `scrape.pages` in `config.yaml` would substantially increase side-effect and dosing information. EDC+R (`--iterations 1`) also helps recall.
